# Визуализатор графа зависимостей Cargo (вариант 25)

Учебный проект по дисциплине «Конфигурационное управление»
(практическая работа № 2): CLI-инструмент для построения и визуализации
графа зависимостей пакетов Rust (Cargo). Готовые менеджеры пакетов и
библиотеки для получения зависимостей не используются — только
стандартная библиотека Python 3.10+.

Текущее состояние: **этап 3 — основные операции**.

## Параметры командной строки

| Параметр | Описание |
|----------|----------|
| `--package ИМЯ` | имя анализируемого пакета (обязательный) |
| `--repo URL\|ПУТЬ` | URL репозитория (по умолчанию `https://index.crates.io`) или путь к файлу тестового репозитория |
| `--test-mode` | режим работы с тестовым репозиторием |
| `--version ВЕРСИЯ` | версия пакета вида `1.2.3` (обязательна вне тестового режима) |
| `--filter ПОДСТРОКА` | не учитывать пакеты, имя которых содержит подстроку |

## Источник данных

Используется sparse-индекс crates.io (`https://index.crates.io`) — тот же,
что читает сам Cargo. Для пакета `serde` файл индекса лежит по адресу
`https://index.crates.io/se/rd/serde`: каждая строка — JSON-описание одной
версии со списком `deps`. Путь строится по правилам Cargo:
1 символ → `1/имя`, 2 → `2/имя`, 3 → `3/первая_буква/имя`,
иначе `первые_2/следующие_2/имя`.

Для каждой зависимости известны: имя (с учетом переименования через
`package`), требование к версии (`req`), вид (`normal`, `build`, `dev`),
признак `optional` и платформа (`target`).

Ошибки репозитория (пакет или версия не найдены, нет сети, ошибка
формата тестового файла) выводятся как `Ошибка: ...`, код возврата 3.

## Построение графа

Модули:

| Модуль | Назначение |
|--------|------------|
| `config.py` | разбор и проверка параметров |
| `cargo.py` | чтение индекса, выбор версии, фичи `default` |
| `semver.py` | требования к версиям Cargo (`^`, `~`, `=`, `>`, `>=`, `<`, `<=`, `*`, списки через запятую) |
| `repository.py` | источники графа: `CargoRepository` (crates.io) и `TestRepository` (файл) |
| `graph.py` | обход BFS с рекурсией, поиск цикла |
| `cli.py` | опции командной строки и вывод |

**Какие зависимости учитываются.** Берутся зависимости видов `normal` и
`build`; `dev` отбрасываются. Опциональная зависимость учитывается, только
если ее включает фича `default` пакета (рекурсивно раскрываются
`"имя_фичи"`, `"dep:имя"`, `"имя/фича"`; слабые `"имя?/фича"` не включают
зависимость). Зависимости для всех платформ (`target`) учитываются.

**Выбор версии.** Для требования вида `^0.2.149` берется наибольшая версия
из индекса, удовлетворяющая требованию: сначала среди релизов без пометки
yanked, затем среди пре-релизов, затем среди отозванных версий.

**BFS с рекурсией.** Функция `bfs_level` обрабатывает текущий уровень
(фронт) обхода: для каждой вершины получает прямые зависимости,
отбрасывает пакеты с подстрокой фильтра и формирует следующий уровень
из еще не посещенных вершин, после чего вызывает себя для следующего
уровня. Глубина рекурсии равна числу уровней графа.

**Фильтр.** Пакет, имя которого содержит подстроку `--filter`, не
попадает в граф, как и пакеты, достижимые только через него.

**Циклы.** Посещенные вершины не раскрываются повторно, поэтому обход
конечен. Дополнительно функция `find_cycle` (DFS) находит и выводит один
из циклов.

## Тестовый репозиторий

Режим `--test-mode`: вместо URL указывается путь к текстовому файлу,
пакеты называются большими латинскими буквами, версия не нужна.

```
# комментарий
A: B C      # A зависит от B и C
B: D
D:          # нет зависимостей
```

Пакет, упомянутый справа, но не описанный слева, считается листом.
Примеры: `examples/repos/` — `simple.txt` (без циклов), `cycle.txt`
(цикл и петля), `diamond.txt` (ромб), `filter.txt` (для фильтра),
`broken.txt` (ошибка формата).

### Обработка ошибок

| Параметр | Ошибка |
|----------|--------|
| `--package` | не задан; недопустимые символы для Cargo; в тестовом режиме — не большие латинские буквы |
| `--repo` | не URL `http(s)://` вне тестового режима; файл не найден в тестовом режиме |
| `--version` | не задана вне тестового режима; не соответствует формату `X.Y.Z` |
| `--filter` | пробелы по краям; подстрока входит в имя самого анализируемого пакета |

При ошибке выводится сообщение `Ошибка: ...` в stderr, код возврата 2.

## Сборка и тесты

Сборка не требуется, нужен Python 3.10+.

```sh
./run.sh --package serde --version 1.0.200   # запуск
make test                                    # модульные тесты
make demo                                    # демонстрационные скрипты
```

## Примеры

```
$ ./run.sh --package A --test-mode --repo examples/repos/cycle.txt

  C -> A
  D -> D

$ ./run.sh --package A --test-mode --repo examples/repos/filter.txt --filter B

  A -> C
  C -> XD
  XD -> (нет)

  proc-macro2 1.0.107 -> unicode-ident 1.0.27
  quote 1.0.47 -> proc-macro2 1.0.107
```
